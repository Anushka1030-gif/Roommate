- [x] **Step 2: Database** — Knex migrations, table schemas (`users`, `email_otps`, `profiles`, `requirements`, `match_results`, `conversations`, `messages`, `blocks`, `reports`, `rate_limit_events`), idempotent admin seeder, DB connection module, `db:reset` helper, and automated integration test with test database (`roomiematch_test`).

Endpoints: `POST /api/auth/register`, `POST /api/auth/verify-otp`, `POST /api/auth/resend-otp`, `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/auth/me`.

- [x] **Step 5: Profile** — Student profile creation and update APIs (`GET /api/profile/me`, `PUT /api/profile/me`, `PUT /api/account/phone`), Knex migrations for user phone, profile age and city, strict Zod validation (enums, age 17-40, cleanliness 1-5, bio max 600 chars, SUPPORTED_CITIES), completeness calculation (16 required fields), privacy protection (no email/phone in profile responses), multi-step onboarding UI (`/onboarding/profile`) with progress indicator, privacy notices, inline errors, settings entry point (`/settings`), login redirection logic, and comprehensive Vitest test coverage across backend and frontend.
- [x] **Step 6: Requirement** — Housing & roommate requirements backend & frontend: `POST /api/requirements` and `GET /api/requirements/active`, complete profile & email verification guards, single-transaction archiving to guarantee exactly one active requirement, Zod validation (budget bounds, cleanliness 1-5, deal-breakers limit, importance weights), matching trigger placeholder hook for Step 7, responsive multi-section form (`/requirement`) with active requirement prefill, importance selectors, route guards, and unit/integration test suites.
- [x] **Step 7: Matching engine** — Deterministic scoring algorithm across 9 lifestyle dimensions (budget overlap, sleep schedule, cleanliness, study habits, food preferences, smoking, drinking, noise tolerance, guest policy), dynamic importance weights weighting, strict SQL hard filters (verified, complete profile, active requirement, same city, overlapping budget, mutual gender compatibility, bidirectional blocks, cleanliness minimums, smoking/drinking rules), shortlist ranking (top 15) and top 3 selection, rule-based fallback explanations, highlights, watch-outs, and icebreakers, automatic execution on requirement submission, cached matches API (`GET /api/matches`, `POST /api/matches/refresh` with 5/day rate limit), 40 realistic demo students seed in Bhopal, and unit/integration test suites (107 total passing tests).
- [x] **Step 8: LLM layer** — Anthropic Claude SDK integration with provider abstraction (`LLMService.rankMatches`), system prompt template from PRD 7.4 (`server/prompts/matching.txt`), compact PII-free JSON payload (verified zero contact details/PII), strict Zod schema validation, automatic single retry on malformed output, hallucinated candidate_id filtering and rule-based shortlist backfilling, 15s timeout with graceful fallback to rule-based ranking, `match_results` table `source` tracking (`llm` vs `fallback`), safe console logging without API key leakage, and complete test suite (15 unit/mock tests, 86 server tests, 36 client tests passing).
- [x] **Step 9: Match results page** — Match cards feed with top 3 AI-ranked candidates, dynamic compatibility score gauges and badges, AI "Why you match" explanations, highlight strength chips, watch-out friction callouts, compact lifestyle summary matrix, expandable 8-dimension compatibility breakdowns, AI icebreaker prompts with instant copy, interactive user actions (optimistic Like, Skip/Restore, Connect/Start Chat), ConnectModal with consent privacy guard, status tabs (All, Suggested, Liked, Connected, Skipped), search and lifestyle quick-filters, daily 5/day refresh button, candidate pool warning banner (< 3 matches), friendly loading shimmer skeletons, complete route guards, backend status action APIs (`PATCH /api/matches/:id/status` and `?status=` filtering), zero PII exposure enforcement, and comprehensive Vitest test coverage (44 client tests passing, zero ESLint errors).
- [x] **Step 10: Chat backend** — Socket.IO real-time event handlers, persistent 1-on-1 message storage, read receipts, and chat history REST endpoints. Features implemented:
  - 1-on-1 conversation creation & retrieval (`POST /api/conversations`) with canonical ID ordering (`user_a_id < user_b_id`), self-chat guards (`400 SELF_CHAT_NOT_ALLOWED`), and bidirectional block checks (`403 USER_BLOCKED`).
  - Inbox overview endpoint (`GET /api/conversations`) returning conversation partners, last message snippet, timestamp, unread count, and strict privacy protection (no email/phone exposure).
  - Paginated chat message history (`GET /api/conversations/:id/messages`) with cursor pagination (`before`, `limit`), participant authorization (`403 FORBIDDEN`), bidirectional block protection, and automatic read-receipt updates for incoming messages.
  - REST message dispatch endpoint (`POST /api/conversations/:id/messages`) with rate limiting (`messageSendLimiter`), Zod body validation (1-1000 chars), atomic transactional storage with conversation timestamp update, and rate-limited email notification dispatch to recipients.
  - Explicit read receipt endpoint (`POST /api/conversations/:id/read`).
  - Socket.IO real-time server (`server/src/sockets/chat.socket.js`) with JWT cookie/handshake authentication middleware, personal user rooms (`user_${userId}`) for live inbox updates, conversation rooms (`conversation_${convId}`), real-time message broadcasting (`new_message`, `inbox_update`), read receipts (`mark_read`, `messages_read`), and typing status indicators (`typing`, `user_typing`).
  - Zod validation schemas (`server/src/validations/conversation.validation.js`) with standardized error envelope and custom error codes.
  - Comprehensive integration test suite (`src/routes/conversations.test.js`) with 18 passing tests covering route guards, authorization, messaging, read receipts, privacy, and Socket.IO handshake authentication (107 total server tests passing, 0 ESLint errors).
